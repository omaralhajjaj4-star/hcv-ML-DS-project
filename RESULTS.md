# Routine lab tests detect liver disease, not its stage

Routine blood tests in the UCI HCV data separate healthy blood donors from liver patients very well, but they cannot reliably say which stage of disease a patient has. In the primary analysis (nested cross-validation, `ml_models.ipynb` cells 97-141), logistic regression with no imbalance correction reaches an AUROC of **0.976 (95% CI 0.949-0.995)** for healthy vs sick and is well calibrated (intercept 0.015, slope 1.10). It finds only **20% of fibrosis patients** among four classes and **50%** among the three disease stages. The sample size calculations in `stats.ipynb` show the data are borderline for healthy vs sick and roughly **22 times too small** for naming the stage. Correcting the imbalance with class weights or SMOTE did not improve ranking and pushed predicted risks too high. The leakage re-analysis of Das et al. (2025) shows why published accuracies near 99% look so good: running SMOTE before the split gives macro F1 0.91 to 1.00, while splitting first gives a **50-seed median of 0.45 to 0.56**, with a drop in all 200 seed-model pairs. The Egyptian COM725 dataset gives chance-level results (24% to 27% accuracy on four balanced stages) and has the statistical fingerprint of randomly generated values, so it serves only as a cautionary note. The weakest points that remain are spectrum bias (donors vs diagnosed patients), the 12% prevalence, no external validation, and the lack of external validation. The TRIPOD+AI items that were missing at the first audit have since been added (section 6.3).

## How to read this file

This file lists every result the repository produces, where it comes from, what it means in plain English, and what it means for the paper *"Machine learning for non-invasive diagnosis of HCV-related liver damage: a critical assessment of performance, validation and leakage"*. In that paper, ML diagnosis is the main work, the leakage re-analysis is a supporting finding, and the Egyptian COM725 dataset is a cautionary note.

**Locations** are given as: notebook > section heading > cell number > first comment line of the code cell. Cell numbers count every cell (markdown and code) from 1 in file order. If the result is also saved as a file, the `results/` file is named. Markdown "Findings" cells are marked "(markdown)".

**All values come from saved outputs**: the saved cell outputs in each `.ipynb` and the files in `results/`. Nothing was re-run for this audit, apart from reading `results/metrics_summary.csv` and the other csv files with pandas. `ml_models.ipynb` was re-run after the fixes in commit `03dca0a`, so its values below are the current ones. Values marked "auditor check" were computed during the audit from the repo data and are not printed by any notebook.

**Terms used** (each is also explained briefly where it first matters):

| Term | Plain meaning |
|---|---|
| AUROC | Chance that the model gives a randomly chosen sick patient a higher risk than a randomly chosen healthy one. 0.5 is a coin toss, 1.0 is perfect. |
| Recall (sensitivity) | Share of patients in a class that the model finds. |
| Macro F1 | Average over classes of F1, where F1 balances recall and precision (how many flagged patients really have the class). Each class counts equally, so rare classes matter. |
| Balanced accuracy | Average recall over the classes. |
| Brier score | Average squared gap between predicted risk and what happened. Lower is better. |
| Log loss | Penalty for giving low probability to the true class. Lower is better. It punishes confident mistakes heavily. |
| Calibration intercept and slope | Whether predicted risks match observed rates. Intercept near 0 and slope near 1 is good. A negative intercept means risks are too high. A slope above 1 means risks are too cautious (pulled to the middle). |
| Cross-validation (CV) | Split the data into k parts, train on k-1, test on the one left out, rotate. Nested CV adds an inner loop for tuning so the test part is never used for tuning. |
| Out-of-fold prediction | A prediction for a patient made by a model that never saw that patient. |
| SMOTE, SMOTE-NC | Creates synthetic patients of rare classes by interpolating between real neighbours. SMOTE-NC handles categorical columns such as sex. |
| Class weights | Makes mistakes on rare classes cost more during training. |
| Leakage | Information from the test patients reaching the training step, which makes scores look better than they are. |
| PPV, NPV | Of those flagged, the share truly sick (PPV); of those cleared, the share truly healthy (NPV). Both depend on prevalence. |
| Net benefit | Decision-curve measure: true positives minus false positives weighted by the chosen risk cut-off, per patient. |
| Bonferroni | Multiplies p-values by the number of tests to limit false positives. |

## 4. ml_models.ipynb part A (cells 1-96): one 80/20 split, superseded

Cells 1-96 use **one stratified 80/20 split** (`random_state=42`), with no cross-validation. The test set holds 122 patients, only **15 sick**, and 4 to 6 per disease class. One patient changes sick recall by about 7 points and a disease-class recall by 17 to 25 points (cell 96 says this itself). These results are **superseded** by part B and should not appear in the paper as performance estimates. They also use correction choices that conflict with the primary design: class weights for binary and three-stage models, and **SMOTENC plus class weights together** for four classes (a double correction).

**Interpretation.** Healthy vs sick is easy: LR and RF reach AUROC 0.97 to 0.99, far above the AST/ALT ratio (0.81). Their intervals overlap, so neither is clearly better. The primary LR gives risks that match observed rates (intercept about 0, slope about 1). Class weights and SMOTE-NC push risks up (intercepts -1.65 and -1.41, CIs exclude 0), almost double the Brier score, and buy only a small rise in sick recall (0.86 to 0.91). Recalibration fixes the average risk but leaves the slope at 1.76, so risks become too cautious. This is the pattern [van den Goorbergh et al. 2022](https://arxiv.org/abs/2202.09101) describe. RF slopes above 1 (1.3 to 1.8) mean its risks are pulled towards the middle.

For four classes, the high AUROC mostly reflects healthy vs not-healthy. The primary model finds **1 in 5 fibrosis patients**, with an interval from 0 to 0.43. For three stages, the honest staging headline is **AUROC 0.84 and fibrosis recall 0.50**: half of fibrosis patients are called hepatitis or cirrhosis. The corrected log loss shows the primary LR beats the majority baseline on both multiclass outcomes (0.204 vs 0.508; 0.779 vs 1.089). The depth-2 decision trees for three stages have log loss of 2.75 to 2.86, much worse than the baseline: they give probabilities close to 0 or 1, and confident mistakes are punished heavily. The best fibrosis recall of any setting (0.743, DT SMOTE-NC) comes with the lowest hepatitis recall (0.171) and macro F1 of 0.494, so it is not a better model.

**What it means for the study.** This is the paper's main result. Report LR with no correction as the primary model, with CIs. Present the binary AUROC of 0.98 as an upper bound, because healthy blood donors vs diagnosed patients is a case-control style comparison that inflates discrimination compared with a real clinic. Present staging as weak and exploratory, in line with the sample size results.

These cannot be fixed with code in this repo:

## Conclusion

The repo now tells one consistent story, and it is stronger than the near-perfect numbers in the literature because it is honest about them. Routine labs answer "is this person a liver patient?" well, but the data cannot support "which stage?", and the sample size results predicted that before any model was trained. The cleanest single argument in the repo is practical, not statistical: an uncorrected logistic regression with a 0.1 cut-off finds 94% of sick patients while flagging 18 per 100, whereas class weights flag 32 per 100 for similar sensitivity. That turns the abstract calibration argument into referral numbers a clinician can weigh.

The main risks for the paper now sit outside the code. The 0.98 AUROC comes from comparing blood donors with diagnosed patients at 12% prevalence, so it is an upper bound until someone tests the model on people actually being worked up for liver damage. The leakage and Egyptian results are most useful as context: one shows how evaluation design can manufacture accuracy, and the other shows that a dataset can contain no signal at all. The stale `findings.md` sections and the missing TRIPOD+AI items have now been fixed, so what is left is external validation, which needs new data.md` sections and adding the missing TRIPOD+AI items, most of which need no retraining, would close the remaining gaps.
